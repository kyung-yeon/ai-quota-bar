# Claude saved reset passes

Claude can grant saved limit resets, including Fable resets. They are separate from paid usage credits and the natural five-hour/weekly reset schedule. Anthropic explains their behavior in [What is a limit reset?](https://support.claude.com/en/articles/17007452-what-is-a-limit-reset) and the [Fable 5.2 launch offer](https://support.claude.com/en/articles/17506494-claude-fable-5-2-launch-offers).

AiQuotaBar requests `GET https://api.anthropic.com/api/oauth/usage?cedar_ember=1` using the existing Claude Code OAuth credential. It preserves the normal usage windows in that response and does not send `skip_spend` or `at_wall`. The query and CLI-shaped User-Agent are observed internal behavior, not a documented public API guarantee: see the [original OAuth observation](https://github.com/steipete/CodexBar/issues/3895) and [independent implementation](https://github.com/steipete/CodexBar/pull/4232). The installed Claude Code 2.1.322 binary also contains the inventory query, `resets_left`, and the `claude-cli/` User-Agent format.

The app reads the installed CLI version with a bounded `--version` command and uses `claude-cli/<version> (external, cli)` for the optional inventory request. If the version cannot be read, it uses the ordinary usage request. HTTP 400 or an ordinary 403 retries once without the inventory query using AiQuotaBar's original request identity. Authentication/scope errors, rate limits, and server failures retain their normal handling. No extra token, browser cookie, account lookup, or login flow is added.

An inventory needs `cedar_ember.eligible: true` and a readable `grants` array. Each grant contributes `resets_left`, rather than one count per grant. Paused, not-yet-started, exhausted, and expired grants are excluded. `usable_now` is deliberately not a balance field: a saved pass can remain while redemption is gated. `ends_at` supplies the expiry; absent dates remain explicitly unknown. Known expirations stop counting before the next refresh. Multiple passes on one grant share a quantity/expiry row.

Missing, ineligible, or malformed inventory is unknown, not zero. It never discards valid quota windows. The card says **Reset passes · not reported by API**; this does not establish that the account has no resets. A valid empty inventory reports zero. The app does not infer passes from `extra_usage`, the weekly reset time, or subscription tenure.

Inventory is display-only. No redemption POST is implemented or sent. Grant IDs and labels are not retained, responses and credentials are not logged, redirects are rejected, and the ephemeral session has no URL cache. This change was compiled locally; no authenticated account fetch or redemption was performed to validate a particular account's eligibility.

# 완료 알림

여러 Codex·Claude Code 세션의 완료 응답을 플로팅 카드로 표시합니다. 처음에는 macOS의 **메인 모니터**에 표시되며, 다른 앱과 전체 화면 Space에서도 **확인** 또는 **모두 확인**을 누를 때까지 유지됩니다. 패널의 상단이나 빈 배경을 드래그해 연결된 다른 모니터로 옮길 수 있습니다. 새 알림이 오거나 앱을 다시 실행해도 옮긴 위치를 기억합니다. 해당 모니터의 연결을 해제하면 메인 모니터로 돌아옵니다.

서비스·세션별로 최신 완료 알림 하나만 표시합니다. 같은 세션에서 다시 완료되면 기존 카드의 내용과 시각을 갱신하고, 이전 이벤트 식별자는 중복 재수신 방지를 위해 보관합니다. 이미 중복으로 쌓인 카드도 불러올 때 하나로 정리하며, 최신 카드를 확인해도 이전 알림이 다시 나타나지 않습니다.

알림은 독립적인 플로팅 창이며, macOS 알림 센터의 배너를 보내지 않습니다. 카드 한 개의 높이는 48pt이며, 서비스 아이콘·프로젝트·세션 이름·상대 완료 시각을 두 줄로 표시합니다. 아이콘에 마우스를 올리면 서비스와 터미널을, 시각에 올리면 정확한 날짜와 시간을 볼 수 있습니다. 프로젝트 이름이나 **↗ 세션 열기**를 누르면 원래 세션으로 이동하며, 이동만으로 확인 처리하지는 않습니다. **✓ 확인**은 해당 알림을 확인 처리합니다. 제목은 행의 남는 너비를 사용하며, 동작 버튼은 정사각형입니다. 아이콘 버튼에는 도움말과 접근성 이름이 있습니다. 창은 다른 앱 창보다 위에 유지되고, 카드 높이에 맞춰 크기를 조절하므로 내부 스크롤이 없습니다. 부모 행만 있으면 한 페이지에 최대 3개, 트리가 있으면 최대 6개(작은 화면에서는 더 적게)를 표시하며 나머지는 이전·다음 버튼으로 확인합니다. 하위 행은 36pt 높이로 줄이고 들여쓰기·연결선을 표시합니다. 페이지가 나뉘면 부모 정보를 함께 반복 표시합니다.

새 알림이 오면 창 전체가 오른쪽 위 모서리를 기준으로 ±3°씩 좌우 세 번 흔들립니다. 이후 12초마다 반복하고, 한 방향으로 움직이는 데 0.11초가 걸립니다. 알림을 확인하면 애니메이션도 중단합니다. macOS의 **동작 줄이기**를 켜면 흔들림이 생략되며, 애니메이션 도중 켜도 즉시 멈춥니다.

메뉴의 **플로팅 미리보기**로 에이전트를 실행하지 않고 예시 카드 두 개를 볼 수 있습니다. 예시임을 화면에 표시하고, 실제 미확인 목록에 저장하거나 개수에 포함하지 않으며 세션 이동 버튼도 비활성화됩니다. 실제 완료가 들어오면 미리보기 대신 실제 알림을 표시합니다. 미확인 항목이 없을 때 **플로팅 열기**를 눌러도 자체 플로팅 창을 표시합니다.

## 열린 세션과 표시 설정

목록은 **확인 필요 → 작업 중 → 대기/열림** 순서입니다. 대기 행은 회색이지만 클릭해 세션으로 이동할 수 있습니다. 작업 중에는 회전 표시가 보이고, 새 완료는 첫 페이지 맨 위로 이동하는 애니메이션을 표시합니다. ‘동작 줄이기’를 켜면 이동·회전을 멈춥니다. 완료를 확인해도 열린 세션은 목록에 남으며, 종료된 세션은 미확인 완료가 있을 때만 남습니다. 모든 행은 스크롤 없이 페이지 버튼으로 볼 수 있습니다.

상단 바 메뉴의 **플로팅 열기 / 플로팅 닫기**와 **모두 확인** 오른쪽 **×**로 표시를 제어합니다. 닫기는 확인 처리나 수집 중단이 아닙니다. 닫힘 상태는 새 완료나 앱 재실행 후에도 유지하며 메뉴에서 다시 열 수 있습니다.

일반 터미널은 세션 시작·입력 이후의 훅 이벤트를 추적합니다. CLI의 PID와 시작 시각을 확보한 경우 종료 훅 없이 끝난 프로세스도 목록에서 제외합니다. 다른 터미널에서 이미 실행 중인 세션은 훅이 활성화된 새 세션이 필요합니다. 과거 대화 이력을 열린 세션으로 간주하지 않습니다. Claude에서 중단 이벤트가 전달되지 않으면 다음 이벤트까지 마지막 상태가 남을 수 있습니다.

실행 중인 로컬 **Orca**는 `terminal list`와 `worktree ps`도 조회하므로 AiQuotaBar 이전에 시작한 연결된 에이전트 탭도 표시합니다. 훅이 없는 세션은 작업 중→완료 전환을 관측하면 완료를 저장하며, 처음 발견한 대기 탭에는 알림을 만들지 않습니다. 조회 사이에 시작·완료된 짧은 작업은 놓칠 수 있어 완료 훅을 우선 사용합니다. 훅이 실제 세션 ID를 제공하기 전까지 런타임 세션은 터미널 handle로 구분합니다. 조회 실패나 불완전한 응답에는 목록을 유지하고 상태를 알 수 없다는 안내를 표시합니다. 현재 Orca 프로필에서 CLI에 노출되는 세션에 한정되며, 모든 네이티브 채팅·원격 런타임·사용자 지정 프로필을 포함하지는 않습니다. 프롬프트·터미널 미리보기·대화 내역은 저장하지 않습니다.

### 하위 에이전트 트리

Codex·Claude Code의 하위 에이전트를 부모 세션 아래에 표시하고, 제공된 관계에 따라 여러 단계로 중첩합니다. 확인이 필요한 항목은 부모·자식 묶음을 유지한 채 위로 올립니다. 하위 행에는 이름이나 역할(없으면 짧은 식별자), 제공된 모델 정보, 실행 상태가 표시됩니다. 같은 터미널 안의 하위 에이전트는 **부모 세션 열기**로 안내하며, 별도 Orca pane을 가진 하위 세션은 해당 pane으로 이동합니다.

Orca의 `children`이 있으면 빈 목록이어도 기존 `subagents`보다 우선합니다. 종료된 자식은 실행 중인 후손을 소유할 때만 부모 구조를 유지하기 위해 남깁니다. 확인할 수 없는 상태에 작업 중 애니메이션을 표시하지 않습니다. 훅에서는 `SubagentStart`·`SubagentStop`을 수집하며, 자식의 응답 완료를 부모 전체의 완료로 알리지 않습니다. 훅만 쓰는 환경에는 자식의 별도 종료를 확실히 알리는 이벤트가 없어, 자식 완료 후 대기로 표시하고 부모가 종료되면 함께 제거합니다. 작업 설명과 자식의 메시지는 저장하지 않습니다.

## 자동 연결

1. 이 빌드의 AiQuotaBar를 계속 사용할 위치에 설치하고 실행해 둡니다.
2. 설치된 Codex·Claude Code CLI를 찾아 자동으로 연결합니다. 별도 메뉴 선택이나 설정 대화 상자는 없습니다.
3. 새 에이전트 세션을 시작합니다. **Codex는 `/hooks`에서 추가된 AiQuotaBar 항목을 검토하고 신뢰해야 합니다.** 자동 등록과 Codex 자체의 신뢰 승인은 별개입니다.
4. 응답이 끝나면 보통 약 2초 이내에 카드가 표시됩니다.

`~/.codex/hooks.json` 또는 `~/.claude/settings.json`에 `SessionStart`, `UserPromptSubmit`, `Stop`, `SessionEnd`, `SubagentStart`, `SubagentStop`과 Codex의 `Interrupt` 또는 Claude의 `StopFailure` 명령 훅을 추가합니다. 다른 도구의 훅과 기존 설정은 유지하며, 변경 전 파일을 같은 폴더의 `*.aiquotabar-backup-<id>`에 백업합니다. 실행 시, 1분마다, **지금 새로고침**을 누를 때 확인하며 같은 설정은 다시 쓰거나 백업하지 않습니다. 설치되지 않은 CLI는 설정 파일도 만들지 않고 건너뛰며, 나중에 설치하면 다음 확인 때 연결합니다.

잘못된 JSON, 심볼릭 링크 설정 파일, 전체 훅 비활성화 설정은 변경하지 않습니다. 연결 실패 시에만 메뉴에 **완료 알림 연결 확인…**이 표시됩니다. 자동 연결은 CLI를 설치하거나 계정에 로그인하지 않습니다.

설치된 앱 실행 파일이 훅을 처리하므로 Python·Node·추가 데몬은 필요하지 않습니다. AiQuotaBar를 종료해도 훅은 완료를 저장하며, 다음 실행 때 미확인 목록을 복원합니다. 앱 위치를 옮겼다면 새 위치에서 실행하면 훅 경로도 자동 갱신됩니다. Codex의 신뢰 승인은 다시 필요할 수 있습니다. 앱을 삭제하기 전에는 연결을 해제하세요.

## 사용자 지정 프로필·에이전트 관리 앱

자동 연결에서는 **AiQuotaBar 실행 환경**의 `CODEX_HOME` / `CLAUDE_CONFIG_DIR`를 사용합니다. Finder는 셸의 환경 변수를 상속하지 않습니다. 별도 프로필을 사용하면 **에이전트를 실행하는 터미널에서** 아래 명령을 실행하세요.

```sh
AQB="/Applications/AiQuotaBar.app/Contents/MacOS/AiQuotaBar"
"$AQB" --install-completion-hooks codex
"$AQB" --install-completion-hooks claude
```

소스 설치라면 경로는 `$HOME/Applications/AiQuotaBar.app/Contents/MacOS/AiQuotaBar`입니다. 같은 환경에서 `--remove-completion-hooks codex` 또는 `--remove-completion-hooks claude`로 해제할 수 있습니다. AiQuotaBar 훅만 제거하고 같은 폴더에 `*.aiquotabar-disabled` 표시 파일을 만들어 자동으로 다시 연결되지 않도록 합니다. 명시적으로 설치 명령을 다시 실행하면 자동 연결도 켜집니다. 설치·해제 후에는 새 세션을 시작하세요. 명령은 설정 파일 경로를 출력합니다.

관리 앱이 매번 다시 생성하는 설정 파일에는 직접 연결하지 마세요. 해당 앱의 영구 훅 설정에서 위 서비스별 이벤트에 `'<앱 실행 파일의 절대 경로>' --completion-hook codex` 또는 `claude`를 등록해야 합니다. 앱마다 프로필·훅 관리 방식이 다르므로 설치만으로 모든 관리 앱의 완료 감지가 자동 연결되지는 않습니다.

세션 이름은 실행 전 설정한 `AIQUOTABAR_SESSION_NAME`, 이벤트가 제공한 세션 이름, 짧은 세션 식별자 순서로 표시합니다.

```sh
AIQUOTABAR_SESSION_NAME="계정 설정 변경" codex
```

## 세션 이동 지원

| 환경 | 이 빌드의 이동 방식 | 조건 |
| --- | --- | --- |
| macOS Terminal | TTY로 기존 탭 선택 | 소유 프로세스의 수명도 검사해 재사용된 TTY를 거부합니다. macOS 자동화 권한이 필요할 수 있습니다. |
| iTerm2 | `iterm2:reveal`로 기존 세션 열기 | 에이전트 환경에 `ITERM_SESSION_ID`가 있어야 하며 iTerm2가 실행 중이어야 합니다. |
| Warp | `WARP_FOCUS_URL`로 원래 세션 열기 | URL을 제공하는 버전과 실행 중인 macOS 안정 버전 Warp가 필요합니다. |
| cmux | AppleScript `focus`로 정확한 surface 선택 | `CMUX_SURFACE_ID`, `CMUX_WORKSPACE_ID`와 AppleScript 지원 버전이 필요합니다. 소켓 접근을 무제한으로 바꾸지 않습니다. |
| Orca | `orca terminal switch`로 세션 선택 | `ORCA_TERMINAL_HANDLE`과 원래 프로필을 사용합니다. 만료된 handle을 폴더명으로 추측해 대체하지 않습니다. 네이티브 채팅은 설치된 Orca가 이 API에 노출하는 세션에 한정됩니다. |
| WezTerm | `wezterm cli activate-pane`으로 pane 선택 | `WEZTERM_PANE`을 사용하며 제공된 `WEZTERM_UNIX_SOCKET`도 보존합니다. |
| kitty | `kitten @ focus-window`로 pane 선택 | `KITTY_WINDOW_ID`, 로컬 `unix:` 방식의 `KITTY_LISTEN_ON`, 기존 원격 제어 허용 설정이 필요합니다. 앱이 kitty 설정을 바꾸지 않습니다. |
| Herdr | 현재 접속한 바깥 터미널과 Herdr 내부 pane 선택 | 아래 래퍼로 접속해야 합니다. 마지막으로 등록한 살아 있는 접속을 대상으로 합니다. |
| Ghostty, VS Code / Cursor 내장 터미널, tmux, screen, SSH | 완료 카드만 표시 | 정확한 탭 이동은 미구현입니다. 별도 세션 연결·확장·원격 중계가 필요합니다. |

이동 대상은 미리 기록한 식별자로 찾으며, 현재 활성 탭·프로젝트 이름·화면 좌표로 추측하지 않습니다. 탭 종료, CLI 미설치, 자동화 권한 거부, 미지원 환경, 식별자 만료 시에는 이유를 표시하고 알림을 유지합니다. 바로 이동할 수 없으면 원래 터미널에서 세션을 직접 열거나 재개하세요. URL 방식에서는 macOS가 URL을 접수한 사실까지만 알 수 있으므로, 열기에 성공했더라도 카드를 자동 확인 처리하지 않습니다.

### Herdr 접속

Herdr 서버는 처음 실행한 터미널보다 오래 살아 있을 수 있습니다. 이전 터미널 정보를 따라가지 않도록 AiQuotaBar를 통해 접속하세요.

```sh
AQB="/Applications/AiQuotaBar.app/Contents/MacOS/AiQuotaBar"
"$AQB" --run-herdr
# 이름이 있는 로컬 세션:
"$AQB" --run-herdr --session work
```

지원되는 바깥 터미널에서 실행하고, 그 안에서 훅이 연결된 Codex·Claude를 사용합니다. 래퍼는 바깥 터미널을 기록한 뒤 자신을 `herdr`로 교체합니다. 에이전트를 추가 생성하거나 입력을 가로채지 않습니다.

알림을 누르면 접속 프로세스의 수명과 Herdr 소켓 식별자를 검사하고, 내부 pane을 선택한 뒤 바깥 탭을 앞으로 표시합니다. 다른 터미널에서 재접속할 때도 래퍼를 사용하세요. 여러 클라이언트가 접속하면 마지막으로 등록한 살아 있는 클라이언트로 이동합니다. 서버가 재시작되면 이전 pane 이동은 차단하므로 원래 터미널에서 세션을 직접 재개해야 합니다. SSH 및 tmux·Herdr 안에 중첩된 접속은 래퍼에서 지원하지 않습니다.

## 완료의 의미

기본 연결은 주 에이전트의 `Stop` 훅, 즉 응답을 마치는 시점을 관찰합니다. **요청한 작업의 성공, 모든 백그라운드 작업의 종료, 다른 Stop 훅의 종료 승인을 검증하는 기능은 아닙니다.** 다른 Stop 훅이 에이전트에게 계속 작업하도록 할 수 있습니다. 세션 종료·중단·실패·하위 에이전트 종료만으로는 카드를 만들지 않습니다.

Codex에서 작업을 이어 가게 하는 Stop 훅을 사용한다면 확정된 [`agent-turn-complete` notify 이벤트](https://learn.chatgpt.com/docs/config-file/config-advanced#notifications)를 권장합니다. **기존 `notify` 설정이 없을 때만** Codex 설정의 최상위에 다음을 추가하세요.

```toml
notify = ["/Applications/AiQuotaBar.app/Contents/MacOS/AiQuotaBar", "--notify-codex"]
```

이 고급 연결 방식으로 바꾸기 전에 `--remove-completion-hooks codex`를 실행해 자동 연결이 `Stop` 훅을 다시 추가하지 않도록 하세요. notify 데이터 자체에 Codex 세션·turn 식별자가 있고 실행 환경에서 터미널 이동 대상을 수집합니다. 다른 도구가 `notify`를 쓰면 덮어쓰지 말고 별도 알림 스크립트에서 두 명령을 연결해야 합니다. AiQuotaBar는 `config.toml`을 자동 수정하지 않습니다. 동일 서비스·세션·turn ID의 중복 이벤트는 하나로 합칩니다.

prompt ID가 없는 구버전 Claude는 `UserPromptSubmit`에서 기록한 토큰을 사용합니다. 세션 중간에 연결해 해당 훅을 받지 못한 경우 응답 해시로 대체하며, 같은 내용의 응답을 중복으로 판단할 수 있습니다.

## 로컬 데이터와 문제 해결

`~/Library/Application Support/AiQuotaBar/Notifications/`에 완료 메타데이터·이동 식별자·Herdr 연결 정보를 저장합니다. 사용자 전용 권한으로 저장하며, 원자적 쓰기와 프로세스 잠금으로 동시 이벤트를 처리합니다. 프롬프트·응답 본문·인증 정보·터미널 출력은 저장하지 않으며 통계나 네트워크 수집도 없습니다.

서비스·세션별 최신 미확인 알림은 만료되지 않습니다. 확인했거나 새 완료로 대체된 이벤트 식별자는 재실행 후 중복을 막기 위해 90일간 보관합니다. 모든 미확인 알림은 페이지 버튼으로 확인할 수 있으며, 현재 페이지에 맞춰 창 크기를 조절하므로 내부 스크롤은 없습니다.

- **일부 세션만 알림이 옴:** 훅 설치·신뢰 승인 전에 실행된 세션은 이전 설정을 계속 사용할 수 있습니다. 해당 작업이 끝난 뒤 Codex를 다시 실행하고 `codex resume`으로 기존 대화를 재개한 다음 `/hooks`에서 AiQuotaBar 항목을 확인하세요. AiQuotaBar만 다시 실행해도 이미 열린 Codex 세션의 설정이 갱신되지는 않습니다.
- **알림이 오지 않음:** 설정 경로, 새 세션 시작, Codex `/hooks` 신뢰 여부, 전체 훅 비활성화 여부를 확인하세요. 관리 앱과 같은 프로필에서 연결해야 합니다.
- **바로 이동하지 못함:** 미리보기는 연결된 실제 세션이 없어 이동 버튼이 비활성화됩니다. 실제 알림이라면 지원 표·자동화 권한·기존 탭 상태를 확인하고, 이동 대상이 없을 때는 원래 터미널에서 세션을 직접 여세요. Herdr는 래퍼로 접속해야 합니다.
- **저장 파일 오류:** 기존 파일을 조용히 초기화하지 않고 보존합니다. 앱을 종료하고 Notifications 폴더를 백업한 뒤 복구하세요.
- **앱 이동:** 새 위치에서 실행하면 자동 연결한 프로필의 경로가 갱신됩니다. 사용자 지정 프로필은 CLI로 다시 연결하세요. **앱 삭제:** 모든 프로필에서 훅 연결을 먼저 해제하세요. 미확인 데이터는 Notifications 폴더를 따로 삭제하기 전까지 남습니다.
